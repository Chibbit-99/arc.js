ARC.JS / DOCUMENTATION

Browser JavaScript, with a runtime.

ARC.js is a browser-side runtime that loads project files from a configuration file, injects ARC modules, and can resolve and bundle NPM packages directly in the browser.

Getting started

ARC.js expects a small project layout. A page loads the runtime with a normal script tag; the runtime then looks for ./arc/config.json relative to that page.

<!-- index.html -->
<script src="https://chibbit-99.github.io/arc.js/main.js"></script>

Create an arc/config.json file and point js at your application entry point.

{
  "modules": ["npmloader.js"],
  "js": ["./src/main.js"]
}
The repository's own demo/arc/ and demo/threejs/ projects use this exact configuration shape.

Project structure

main.js

The core startup runtime. It loads config.json, fetches modules, executes arc/init.js when present, and runs the configured project JavaScript files.

module/npmloader.js

An ARC module that exposes browser-side NPM loading through importPackage() and importGlobal().

arc/config.json

Declares which ARC modules to load and which project JavaScript files should execute.

arc/init.js

Optional async initialization code. It executes before project JavaScript and can use await importPackage(...).

src/

Your application code. The runtime supports one JavaScript path or an array of paths in config.json.

demo/threejs/

A working example that imports Three.js through ARC.js and builds a 3D scene entirely in the browser.

config.json

The runtime requires modules to be an array. The js property is optional and may be either one path or an array of paths.

Modules

{
  "modules": [
    "npmloader.js"
  ]
}

Each module name is fetched from the ARC.js module directory. A configured module is fetched, converted to text, injected as a script, and loaded before arc/init.js.

JavaScript entry points

{
  "js": [
    "./src/components.js",
    "./src/main.js"
  ]
}

All configured JavaScript files are fetched concurrently. They are then executed in the same order in which they appear in the configuration.

Startup sequence

01   Load ./arc/config.json
02   Validate config.modules
03   Fetch and inject configured ARC modules
04   Load and await ./arc/init.js when it exists
05   Fetch configured project JavaScript files
06   Execute project files in config order
07   Project startup complete

If arc/init.js does not exist, ARC.js warns and continues. If js is missing, no project JavaScript files are executed.

NPM packages in the browser

The NPM loader is the largest runtime module currently shipped with ARC.js. It talks to the NPM registry, downloads package tarballs, extracts them into an in-memory virtual filesystem, resolves package entry points and dependencies, bundles the result with esbuild-WASM, and injects the compiled ESM bundle.

NPM registry metadata
Package tarball (.tar.gz)
In-memory virtual filesystem
package.json / exports / browser resolution
Dependency tree
esbuild-WASM bundle
Injected module script

The loader currently uses esbuild-WASM 0.28.1 and fflate 0.8.2 for browser-side compilation and gzip extraction.

importPackage()

await importPackage(specifier)
specifier can be a package name, scoped package, optional version/range, or package subpath. The function returns the imported module namespace.
const three = await importPackage("three");

const tesseract = await importPackage("tesseract.js");

// Versions and subpaths are parsed by ARC.js.
const helpers = await importPackage("some-package@1.2.3/helpers");

Imports are cached by the exact requested specifier. A later call with the same specifier returns the cached module instead of recompiling it.

importGlobal()

importGlobal(packageName, exportKey, alias)
packageName must already have been imported. exportKey names an export from that cached module. alias optionally controls the name assigned to globalThis.
await importPackage("three");
importGlobal("three", "ArrowHelper");

// Or choose another global name.
importGlobal("three", "Vector3", "Vec3");
importGlobal() deliberately does not import packages for you. It is synchronous convenience around an already-cached import, so network and compilation work stays inside importPackage().

Package resolution

The loader parses normal and scoped package specifiers, optional versions, subpaths, and several common semver forms. Package entry resolution considers exports, direct subpaths, browser entries, module, main, and finally index.js.

For conditional exports, the browser-oriented preference is browser → import → module → default → require. Relative package imports are resolved inside the package's virtual filesystem, while bare imports are checked against the importing package's declared dependencies.

The loader also understands CommonJS/ESM interop at the module boundary and re-projects enumerable properties attached to a default CJS export so common hybrid packages can expose named properties to browser code.

ARC modules

Modules are optional pieces of runtime functionality. main.js loads each name in config.modules from:

https://chibbit-99.github.io/arc.js/module/<module-name>

That separation is intentional: the startup runtime stays responsible for bootstrapping projects, while functionality such as NPM loading lives in an independent module.

Debugging

ARC.js logs its startup process with the [ARC] prefix. The NPM loader also exposes globalThis.ARC for inspection, including package/module caches and its initialized compiler tools.

console.log(ARC);
console.log(await importPackage("three"));

When package loading fails, importPackage() logs the package specifier and rethrows the underlying error so it is visible to the calling code.
